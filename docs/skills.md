# Skills

A skill is a focused set of instructions applied to a chat. When a skill is active, its
instructions join the system prompt for every turn of that conversation.

## Anatomy

| Field | Meaning |
|---|---|
| `name` | Display name, e.g. "Recipe scaler" |
| `slug` | The `/trigger`; lowercase letters, digits, and hyphens; unique |
| `description` | One line saying what the skill does — used to decide when to load it |
| `emoji` | Shown next to the skill in lists and on the composer chip |
| `instructions` | The text appended to the system prompt (8,000 characters max) |

## Using a skill

- **From the composer.** Type `/` to filter the skill list, then pick one — a leading
  `/slug` is applied to the conversation and stripped from the message.
- **From the skill picker.** Tap the skill chip beside the composer.
- **Before the first message.** Picking a skill on an empty chat stores it as pending; it is
  applied to the conversation created by the next send.

The active skill is stored on the conversation, so it survives app restarts and is carried
in an export. The chip's × clears it.

## Managing skills

**Settings → Connectors → Skills** lists everything available and lets you create, edit, and
delete your own. Slugs must be unique across bundled and user skills. Bundled skills cannot
be edited — duplicate one to get an editable copy.

## Bundled skills

There is deliberately exactly one skill compiled into the app: **Skill maker**
(`/skill-maker`), the skill that writes skills. Everything else is meant to be yours —
written by hand in the skills sheet, or generated by the assistant.

Bundled skill ids are stable (`builtin:<slug>`) so a conversation keeps its skill across app
updates.

## The model's own access

Two tools let the assistant work with skills mid-run:

- **`load-skill`** pulls a skill's instructions into the conversation. Its description is
  rebuilt on every run to carry the current catalog — slug and one-line description for each
  skill — so the model can recognize when a request matches one.
- **`create-skill`** saves a new skill. The instruction text tells the model to call it only
  after you have confirmed the content, and to write instructions as directives ("You are
  acting as…") stating role, procedure, output format, and edge cases.

A created skill is immediately usable by its `/slug` and editable in Settings.

## Writing good instructions

The bundled Skill maker encodes the guidance, but in short:

- Write directives to the assistant, not documentation about it.
- State the role, the exact working procedure, the output format, and what to do with
  unclear input, missing data, and out-of-scope requests.
- Name the app's tools the skill should lean on (`web-search`, `web-fetch`,
  `calendar-events`, `get-location`, `save-memory`, …).
- Keep it tight — every sentence should change behavior.
- Lead the description with *what the skill does*, not how, since it is what the model reads
  when deciding whether to load it.
- Skills only shape instructions. They cannot add capabilities the app does not have.
